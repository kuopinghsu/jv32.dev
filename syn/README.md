# jv32 SoC — Synthesis & P&R with OpenRAM + OpenLane2 (Nangate 45nm)

## Overview

This directory implements the full physical implementation flow for `jv32_soc`:

1. **OpenRAM** compiles the TCM SRAM macros with the Nangate 45nm (FreePDK45) process.
2. **OpenLane2** runs the Classic flow: synthesis → floorplan → placement → CTS → routing → signoff.

## Prerequisites

### 1. Tools

| Tool | Source | Required for |
|------|--------|-------------|
| OpenRAM 1.2.48 | `$HOME/opt/OpenRAM` | SRAM macro compilation |
| OpenLane 2.x | `$HOME/opt/openlane2` | Synthesis + P&R |
| Python 3.8+ | system | running OpenRAM scripts |

### 2. Nangate 45nm Open Cell Library (FreePDK45)

The full Nangate OpenCellLibrary is required for P&R (LEF + GDS).
The timing lib (`NangateOpenCellLibrary_typical.lib`) is already checked in to `syn/pdk/`.

Download the complete FreePDK45 release from NC State University:
<https://www.eda.ncsu.edu/wiki/FreePDK45>

After download, set `NANGATE_HOME` in `env.config`:

```
NANGATE_HOME=/path/to/FreePDK45/NangateOpenCellLibrary
```

Expected files under `NANGATE_HOME`:
- `NangateOpenCellLibrary.tech.lef`
- `NangateOpenCellLibrary.macro.lef` (or `.macro.mod.lef`)
- `NangateOpenCellLibrary.gds`
- `lib/NangateOpenCellLibrary_typical.lib` *(optional; local copy is used otherwise)*

### 3. env.config

Add the following to `$PROJECT_ROOT/env.config`:

```makefile
# ── ASIC flow tools ──────────────────────────────────────────────────────────
OPENRAM      = $(HOME)/opt/OpenRAM
OPENLANE     = $(HOME)/opt/openlane2
OPENROAD     = $(SYN_DIR)/scripts/openroad_nix.sh
NANGATE_HOME = /path/to/FreePDK45/NangateOpenCellLibrary
```

## Quick start

```bash
cd syn/

# 1. Create the local Python venv for OpenRAM
make openram-setup

# 2. Pre-fetch Nix packages for OpenLane2 / OpenROAD (~500 MB, once only)
make syn-setup

# 3. Compile the SRAM macros (Nangate 45nm, 16 KB IRAM + DRAM — evaluation)
make gen-mem

# 4. Run OpenLane2 (synthesis + place + route + signoff)
make synth
```

Results land in `build/openlane_run/`.

## SRAM macro details

jv32 TCM memories are currently configured for **16 KB** each (evaluation).
Each TCM is decomposed into 2 × `sram_1rw_1024x64` sub-banks:

```
IRAM (16 KB) = 2 × sram_1rw_1024x64   (1024 words × 64-bit,  addr[10] = bank select)
DRAM (16 KB) = 2 × sram_1rw_1024x64   (same macro,  4 instances total)
```

### Macro physical parameters (`words_per_row = 4`)

| Parameter | Value |
|---|---|
| Configuration | 1024 words × 64-bit, 8 write-mask bits |
| `words_per_row` | 4 — 256 rows, 256 bits/row (~1:1.6 W:H aspect ratio) |
| LEF SIZE | **247.88 × 386.12 µm** |
| 4-macro footprint | 1249.02 µm wide × 406.12 µm tall (at y = 20 µm) |

The RTL source (`rtl/jv32_soc.sv`, `rtl/jv32/jv32_top.sv`) retains 128 KB as its
module-parameter default; the synthesis build overrides to 16 KB via
`SYNTH_PARAMETERS` in `openlane/config.yaml` and `IRAM_BANKS`/`DRAM_BANKS` in
`syn/Makefile` (each bank is one `sram_1rw_1024x64` = 8 KB).

To switch to a different TCM size, update both those two locations and
add/select the matching generate-branch in `syn/lib/sram_1rw.sv`:

```bash
# Example: 64 KB each (8 banks × 8 KB)
make gen-mem IRAM_BANKS=8 DRAM_BANKS=8
```

## OpenLane2 flow details

The `openlane/config.yaml` targets:
- **PDK**: `freepdk45` (Nangate 45nm Open Cell Library)
- **Clock**: 80 MHz (12.5 ns period)
- **Core utilisation**: 45% placement density (`PL_TARGET_DENSITY: 0.45`)
- **Global routing**: up to Metal9

The custom PDK configuration lives in `pdk/freepdk45/libs.tech/openlane/`.
OpenLane2 is invoked with `--pdk-root $(CURDIR)/pdk --pdk freepdk45`.

### Current synthesised configuration

The parameters below are written to `build/tcm_params.yaml` by `make synth` /
`make gen-mem` and are passed to Yosys via `SYNTH_PARAMETERS`:

| Parameter | Value | Description |
|---|---|---|
| `IRAM_BANKS` | `2` (16 KB) | IRAM sub-bank count (1 bank = 8 KB) |
| `DRAM_BANKS` | `2` (16 KB) | DRAM sub-bank count (1 bank = 8 KB) |
| `FAST_MUL` | **`1`** | Multiplier enable (1 = fast path) |
| `MUL_MC` | **`1`** | 2-stage pipelined multiplier (requires `FAST_MUL=1`) |
| `FAST_DIV` | **`0`** | Serial restoring divider (variable latency) |
| `FAST_SHIFT` | **`1`** | Barrel shifter (1-cycle) |
| `BP_EN` | **`1`** | Branch predictor enabled |
| `IBUF_EN` | **`1`** | Instruction buffer enabled |
| `ZCMP_EN` | **`1`** | Zcmp extension enabled |

To change any parameter pass it on the `make` command line, e.g.:

```bash
make synth FAST_MUL=1 FAST_SHIFT=1
```

The overall 88.9% gating rate is close to the theoretical maximum; the remaining ungated FFs are the CDC synchronizer chains in `jtag_top` described below.

#### Why `jtag_top` is lower (~71%)

`jtag_top` contains all CLK ↔ TCK clock-domain crossing (CDC) logic for the debug
interface.  Two-stage synchronizer chains on both sides of the domain boundary
**must sample on every clock edge** to guarantee metastability resolution; gating
their clock would violate the synchronizer setup time and defeat the purpose.

The 362 ungated FFs (1,248 − 886) are split across two modules:

**CLK → TCK** (in `jtag_tap`, clocked by `tck_i` — ~92 bits)
Status and result signals driven by `jv32_dtm` in the CLK domain are captured into
the TCK domain so the JTAG probe can read them during DMI scans:

| Synchronizer | Bits | Purpose |
|---|---:|---|
| `busy_tck_chain[1:0]`, `sba_busy_tck_chain[1:0]` | 4 | cmd-busy / SBA-busy back to probe |
| `halted_tck_chain[1:0]`, `resumeack_tck_chain[1:0]` | 4 | hart halted / resume-ack status |
| `cmderr_sync[1:0]` (3-bit) | 6 | abstract-command error code |
| `sb_err_tck_chain[1:0]` (3-bit) | 6 | SBA error bits |
| `data0_result_sync[1:0]` (32-bit) | 64 | abstract-command read-back data |
| `data0/1/sbdata0/sbaddress0_result_valid_sync[1:0]` | 8 | result-valid handshake bits |

**TCK → CLK** (in `jv32_dtm`, clocked by `clk` — ~270 bits)
JTAG-written payloads and toggle handshakes are captured from the TCK domain into
the CLK domain so the debug module can act on them:

| Synchronizer | Bits | Purpose |
|---|---:|---|
| `command_reg_tck_sync[1:0]` (32-bit) | 64 | command register payload |
| `data0_tck_sync[1:0]`, `data1_tck_sync[1:0]` (32-bit each) | 128 | abstract-command write data |
| `sbaddress0_stable_sync[1:0]` (32-bit) | 64 | SBA address payload |
| `sb_access_tck_sync[1:0]` (3-bit), `sb_autoincr_tck_sync[1:0]` | 8 | SBA control bits |
| Toggle handshakes (cmd\_wr, sba\_wr/rd, cmderr\_clr, sb\_err\_clr, …) | ~16 | write-valid and clear toggles |

These synchronizer FFs must toggle freely during debug accesses.  This is
**architecturally correct** — CDC synchronizers require free-running clocks.
